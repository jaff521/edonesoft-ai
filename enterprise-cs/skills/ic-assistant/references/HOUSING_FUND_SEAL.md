# 公积金封存 (HOUSING_FUND_SEAL)

> 本文档为 ic-assistant 在处理「公积金封存」人事事项时的业务参考文档。

---

## 办理逻辑

### 一、确认企业与员工基本信息

- 复用 Step 1 中已查询的企业名称和统一社会信用代码。
- 收集员工姓名与身份证号码。若客户提供了身份证照片，自动调用 `validate_document.py` 识别提炼姓名与 18 位身份证号。

### 二、收集公积金封存扩展明细

逐步收集以下公积金封存所需信息：

| 字段 | 必填 | 默认与处理规则 |
|------|------|----------------|
| 员工姓名 | ✅ | 身份证姓名 |
| 身份证号 | ✅ | 18 位身份证号码 |
| 公积金账号 | ✅ | 员工公积金账号 |
| 退工日期 | ❌ | 格式 `yyyy-MM-dd`（可选） |
| 封存原因 | ❌ | 如 "员工离职"（可选） |

---

### 三、汇总确认与建单（强约束步骤）

将所有收集到的信息**逐字段**汇总展示给客户：

> 【公积金封存工单信息汇总】
> 
> 销方企业：上海星辰贸易有限公司
> 业务类型：公积金封存
> 
> 员工信息：
> - 员工姓名：赵六
> - 身份证号：310101199606061234
> - 公积金账号：310000000067890
> - 退工日期：2026-08-31
> - 封存原因：员工离职
> 
> 请核对以上信息是否正确。确认无误请回复“确认”，我将为您创建公积金封存工单。

> [!IMPORTANT]
> **必须在用户明确回复“确认”后方可触发建单**：严禁自动或提前触发 `hr-creator` Skill 创建工单。

---

## 字段结构规范

客户确认后，组装以下 JSON 调用 `hr-creator` Skill：

```json
{
  "sessionKey": "{sessionKey}",
  "workOrder": {
    "enterpriseName": "{企业名称}",
    "creditCode": "{统一社会信用代码}",
    "orderType": "BIZ_HOUSING_FUND_SEAL"
  },
  "housingFundSealDetail": {
    "employeeName": "{员工姓名}",
    "idCard": "{身份证号}",
    "fundAccount": "{公积金账号}",
    "leaveDate": "2026-08-31",
    "sealReason": "员工离职"
  }
}
```
