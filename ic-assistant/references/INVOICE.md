# 发票开票 (INVOICE)

> 本文档为 ic-assistant 在处理「发票开票」事项时的业务参考文档。

---

## 办理逻辑

### 一、确认销方企业信息

- 复用 Step 1 中已查询的企业名称和统一社会信用代码作为销方信息
- 向客户确认是否正确

### 二、收集购方信息与开票配置

逐步收集以下信息：

| 字段 | 必填 | 默认与处理规则 |
|------|------|----------------|
| 购买方名称 | ✅ | 对方公司全称 |
| 购买方统一社会信用代码 | ❌ | 按以下优先级处理：**①** 若客户已主动提供，直接使用；**②** 若客户未提供且购方为企业（名称含"公司"、"有限"、"集团"等），助手**必须**自动调用 `python3 {baseDir}/scripts/unified_query.py "{购买方名称}"` 查询，查到后向客户展示并请客户确认无误后填入 `buyerCreditCode`；**③** 若查询不到，则留空不填 |
| 发票类型 | ✅ | **默认蓝字发票（`BLUE_INVOICE`）**。无需向客户询问蓝字还是红字，全部默认蓝字发票（除非客户主动明确提出要冲红/红字） |
| 发票类别与税率 | ✅ | **结合销方企业纳税人资质自动匹配，免去询问**：<br>• **小规模纳税人**：发票类别默认 `NORMAL_INVOICE`（增值税普通发票），默认税率 `1%`<br>• **一般纳税人**：发票类别默认 `SPECIAL_VAT_INVOICE`（增值税专用发票），默认税率根据业务类型取行业标准（如现代服务业 `6%`） |
| 开票备注 | ❌ | 如项目名称、合同编号等（可选） |

---

### 三、收集开票明细行

逐行收集，每行包含：

| 字段 | 必填 | 说明 |
|------|------|------|
| 项目名称 (itemName) | ✅ | 格式：`*税收分类编码简称*客户货物名称`（如 `*鉴证咨询服务*法律服务`、`*信息技术服务*软件技术服务费`）。其中简称来自 `tax_query.py` 返回的 `shortName`，货物名称为客户实际业务描述 |
| 税收分类编码 | ✅ | **商品和服务税收分类编码（19位纯数字，必填）**。必须通过 `tax_query.py` 检索并由客户确认选择 |
| 规格型号 | ❌ | |
| 单位 | ❌ | 如"项"、"次"、"套"、"个"、"台"等。当客户表述中包含了数量和单位时**必须准确提取出单位字符**填入；若客户未提及单位，则 `unit` 留空不填 |
| 数量 | ✅ | 数量（须大于0）。**客户未说明数量时默认为 1** |
| 金额 | ✅ | **客户提供的金额默认为含税金额**。助手直接询问金额即可，**无需追问是否含税**——若客户未特别说明则默认含税。脚本会自动换算 |
| 税率 | ✅ | 结合企业资质默认：小规模企业默认 `1%`；一般纳税人现代服务业默认 `6%` |

> [!IMPORTANT]
> **金额处理与自动换算规则（接口已更新）**：
> 1. **客户金额默认含税**：客户在群里说的金额**默认视为含税金额**，无需追问"是否含税"。只有当客户主动声明是不含税金额时，才另行处理。
> 2. **数量默认为1**：若客户未明确说明数量，默认 `quantity = 1`。
> 3. **脚本自动换算**：`invoice_creator.py` 会自动将含税金额换算为接口所需的不含税字段：
>    - `amount`（不含税金额）= `含税金额 / (1 + 税率)`
>    - `unitPrice`（不含税单价）= `amount / quantity`
>    - `taxAmount`（税额）= `含税金额 - amount`
>    - `taxRate` 自动转为小数形式（如 `6%` → `0.06`）
> 4. 助手组装 JSON 时，将客户提供的含税金额填入 `amount` 字段即可（脚本内部会识别为含税金额并自动换算）。

> [!IMPORTANT]
> **项目名称（itemName）格式规范**：
> `itemName` 必须按 `*{税收分类编码简称}*{客户货物名称}` 格式填写：
> - `税收分类编码简称`：来自 `tax_query.py` 查询结果中的 `shortName`（如 "鉴证咨询服务"、"信息技术服务"）
> - `客户货物名称`：客户实际描述的服务或商品名（如 "法律服务"、"软件技术服务费"）
> - 示例：`*鉴证咨询服务*法律服务`、`*信息技术服务*软件技术服务费`

> [!IMPORTANT]
> **税收分类编码交互选择流程（仅展示简称 shortName）**：
> 1. **提取关键字并查询**：提取客户给出的开票项目/关键字，**必须**先调用：
>    ```bash
>    python3 {baseDir}/scripts/tax_query.py "{关键字}"
>    ```
> 2. **展示候选列表供客户选择（仅显示简称）**：
>    > 为您检索到以下税收分类选项，请确认选择：
>    > 1. 信息技术服务（编码：`3040201020000000000`）
>    > 2. 生产生活服务（编码：`3040102000000000000`）
> 3. **客户确认锁定**：客户选择序号后，锁定 `shortName`（用于拼接 itemName）和 19 位 `goodsServiceTaxCode`。
> 4. **未检索到处理**：提示客户提供更通用的关键字，重新查询。

询问客户是否还有更多明细行，直到客户确认收集完毕。

### 四、汇总确认与二次确认建单（强约束步骤）

将所有收集到的开票信息**逐字段**汇总展示给客户，**每个必填字段必须单独标注呈现**。格式示例：

> 【开票信息汇总】
> 
> 销方：湖北仁东食品有限公司（小规模纳税人）
> 销方信用代码：91420600MABTUNYF9M
> 购方：北京某科技有限公司
> 购方信用代码：91110108MA01XXXXX（请核对）
> 发票类型：蓝字发票（默认）
> 发票类别：增值税普通发票（默认）
> 
> 明细第1行：
> - 项目名称：*信息技术服务*软件技术服务费
> - 税收分类编码：3040201020000000000
> - 数量：1
> - 单位：项
> - 金额（含税）：10000元
> - 税率：1%
> 
> 请核对以上信息是否正确。确认无误请回复"确认"，我将为您创建开票工单。

> [!IMPORTANT]
> **汇总信息逐字段呈现规则（严格强制）**：
> 1. **明细行每个必填字段必须单独一行显式标注**，包括：项目名称（`*简称*货物名称` 格式）、税收分类编码、数量、单位（若有）、金额（含税）、税率。
> 2. **严禁使用紧凑一行格式**。
> 3. 确认消息中呈现的每个字段，在后续组装 JSON 时**必须一一对应填入**。

> [!IMPORTANT]
> **必须在用户明确回复"确认"后方可触发建单**。

## 字段结构规范

客户确认后，组装以下 JSON 调用 `invoice-creator` Skill：

```json
{
  "sessionKey": "{sessionKey}",
  "workOrder": {
    "enterpriseName": "{销方企业全名}",
    "creditCode": "{销方统一社会信用代码}"
  },
  "invoiceOrder": {
    "buyerName": "{购买方名称}",
    "buyerCreditCode": "{购买方信用代码}",
    "invoiceType": "{BLUE_INVOICE 或 RED_INVOICE}",
    "invoiceCategory": "{SPECIAL_VAT_INVOICE 或 NORMAL_INVOICE}",
    "invoiceRemark": "{开票备注}"
  },
  "invoiceDetailList": [
    {
      "itemName": "*{税收分类编码简称}*{客户货物名称}",
      "goodsServiceTaxCode": "{选定的19位税收分类编码}",
      "spec": "{规格型号}",
      "unit": "{单位}",
      "quantity": "{数量，默认1}",
      "amount": "{客户提供的含税金额}",
      "taxRate": "{税率，如6%或0.06}"
    }
  ]
}
```

> [!NOTE]
> 助手组装 JSON 时，`amount` 直接填入客户提供的含税金额即可。`invoice_creator.py` 脚本内部会自动换算为不含税金额(`amount`)、不含税单价(`unitPrice`)、税额(`taxAmount`)、小数税率(`taxRate`)，最终提交给后端接口。

### 字段映射说明

| 客户表述 | 字段值 |
|----------|--------|
| 蓝字发票 / 正常开票 | `invoiceType: "BLUE_INVOICE"` |
| 红字发票 / 冲红 | `invoiceType: "RED_INVOICE"` |
| 专票 / 增值税专用发票 | `invoiceCategory: "SPECIAL_VAT_INVOICE"` |
| 普票 / 普通发票 | `invoiceCategory: "NORMAL_INVOICE"` |

---

## 注意事项

1. 开票工单调用的 Skill 是 `invoice-creator`（不是 `ticket-creator`）
2. 开票工单创建成功后无 H5 确认页，回复模板为：
   > ✅ 开票工单已创建，工单号：`{ticket_id}`。请等待经办人确认后进行后续开票操作。
3. 如果客户同时选择了工商变更事项和发票开票，需要分别创建两个独立的工单
