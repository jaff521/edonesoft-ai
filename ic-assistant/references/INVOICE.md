# 发票开票 (INVOICE)

> 本文档为 ic-assistant 在处理「发票开票」事项时的业务参考文档。

---

## 办理逻辑

### 一、确认销方企业信息

- 复用 Step 1 中已查询的企业名称和统一社会信用代码作为销方信息
- 向客户确认是否正确

### 二、收集购方信息

### 二、收集购方信息与开票配置

逐步收集以下信息：

| 字段 | 必填 | 默认与处理规则 |
|------|------|----------------|
| 购买方名称 | ✅ | 对方公司全称 |
| 购买方统一社会信用代码 | ❌ | 按以下优先级处理：**①** 若客户已主动提供，直接使用；**②** 若客户未提供且购方为企业（名称含"公司"、"有限"、"集团"等），助手**必须**自动调用 `python3 {baseDir}/scripts/unified_query.py "{购买方名称}"` 查询，查到后向客户展示并请客户确认无误后填入 `buyerCreditCode`；**③** 若查询不到，则留空不填 |
| 发票类型 | ✅ | **默认蓝字发票（`BLUE_INVOICE`）**。无需向客户询问蓝字还是红字，全部默认蓝字发票（除非客户主动明确提出要冲红/红字） |
| 发票类别与税率 | ✅ | **结合销方企业纳税人资质自动匹配，免去询问**：<br>• **小规模纳税人**：发票类别默认 `NORMAL_INVOICE`（增值税普通发票），默认税率 `1%`<br>• **一般纳税人**：发票类别默认 `SPECIAL_VAT_INVOICE`（增值税专用发票），默认税率根据业务类型取行业标准（如现代服务业 `6%`） |
| 开票备注 | ❌ | 如项目名称、合同编号等（可选） |

---

### 三、收集开票明细行

逐行收集，每行包含：

| 字段 | 必填 | 说明 |
|------|------|------|
| 项目名称 | ✅ | 选定的标准税收分类名称（如"系统软件产品"、"工业自动控制系统"等） |
| 税收分类编码 | ✅ | **商品和服务税收分类编码（19位纯数字，必填）**。必须通过 `tax_query.py` 检索并由客户确认选择 |
| 规格型号 | ❌ | |
| 单位 | ❌ | 如"项"、"次"、"套"、"个"、"台"等。**单位提取规则**：当客户表述中包含了数量和单位（例如"1项"、"2次"、"5台"、"100套"），**必须准确提取出单位字符**（如"项"、"次"、"台"、"套"）填入 `unit` 字段并提交；若客户未提及单位，则 `unit` 留空不填（无需强行补充）。 |
| 数量 | ✅ | 数量（须大于0） |
| 金额 | ✅ | **含税总金额（元，必填，保留最多 4 位小数）**。助手**不再询问单价，而是直接询问含税金额**。换算与确认规则见下方说明 |
| 单价 | ✅ | **含税单价（元）**。由助手根据 `amount ÷ quantity` 自动计算（**除不尽时保留 13 位小数**） |
| 税率 | ✅ | 结合企业资质默认：小规模企业默认 `1%`；一般纳税人现代服务业默认 `6%` |

> [!IMPORTANT]
> **金额（amount）含税确认与单价（unitPrice）计算规则（强制步骤）**：
> 1. **询问含税总金额**：助手**不再向客户询问单价**，而是直接询问项目的含税总金额。
> 2. **金额含税确认与换算**：
>    - 若客户确认**已是含税金额**：直接使用该金额作为 `amount`（保留最多 4 位小数）。
>    - 若客户提供的是**不含税金额**：按 `含税金额 = round(不含税金额 × (1 + 税率), 4)` 计算并向客户确认（例如：“您提供的不含税金额 10000 元，按 6% 税率计算，含税总金额为 10600.00 元，请确认是否按 10600.00 元提交？”）。
> 3. **自动计算含税单价（除不尽保留13位小数）**：
>    - 确定含税金额 `amount` 与数量 `quantity` 后，助手自动计算 `unitPrice = amount / quantity`。
>    - 若整除（如 10000 ÷ 2 = 5000），`unitPrice` 为 `5000`；**若除不尽（如 100 ÷ 3），`unitPrice` 保留 13 位小数**（即 `33.3333333333333`）。

> [!IMPORTANT]
> **税收分类编码交互选择流程（仅展示简称 shortName）**：
> 1. **提取关键字并查询**：提取客户给出的开票项目/关键字（如"软件开发"、"咨询费"），**必须**先调用查询脚本：
>    ```bash
>    python3 {baseDir}/scripts/tax_query.py "{关键字}"
>    ```
> 2. **展示候选列表供客户选择（仅显示简称）**：
>    将返回的 `candidates` 列表以清晰的序号形式罗列给客户。**服务类型仅显示简称（`shortName` / `displayName`，如“计算机配套产品”）**，不再拼装全称：
>    > 为您检索到以下税收分类选项，请确认选择：
>    > 1. 计算机配套产品（编码：`1090512010000000000`）
>    > 2. 生产生活服务（编码：`3040102000000000000`）
>    > ...
> 3. **客户确认锁定**：客户选择序号（或确认具体项目）后，锁定该分类对应的标准项目名称 `itemName` 与 19 位 `goodsServiceTaxCode`。
> 4. **未检索到处理**：若返回列表为空，提示客户：“未找到相关的税收分类，请提供更通用或准确的关键字（例如‘软件’、‘咨询’、‘设计’等）”，收到新关键字后重新执行 `tax_query.py`，直到检索成功并经客户确认锁定时为止。

询问客户是否还有更多明细行，直到客户确认收集完毕。

### 四、汇总确认与二次确认建单（强约束步骤）

将所有收集到的开票信息汇总展示给客户，并明确提示回复“确认”：

> 开票信息汇总：
> 销方：湖北仁东食品有限公司（小规模纳税人）
> 购方：北京某科技有限公司
> 购方信用代码：91110108MA01XXXXX（请核对）
> 类型：蓝字普通发票（默认）
> 明细：
>   1. 计算机配套产品（编码：1090512010000000000） × 1项 × 10000元（含税总额），单价 10000元，税率1%
> 
> 请确认以上开票信息是否无误。确认后请回复“确认”，我将为您创建开票工单。

> [!IMPORTANT]
> **必须在用户明确回复“确认”后方可触发建单**：在展示汇总信息后，**严禁自动或提前触发脚本创建工单**。助手必须等待用户回复“确认”或“确认提交”后，方可运行 `invoice-creator` Skill 创建工单，避免随意创建。

## 字段结构规范

客户确认后，组装以下 JSON 调用 `invoice-creator` Skill：

```json
{
  "sessionKey": "{sessionKey}",
  "workOrder": {
    "enterpriseName": "{销方企业全名}",
    "creditCode": "{销方统一社会信用代码}"
  },
  "invoiceOrder": {
    "buyerName": "{购买方名称}",
    "buyerCreditCode": "{购买方信用代码}",
    "invoiceType": "{BLUE_INVOICE 或 RED_INVOICE}",
    "invoiceCategory": "{SPECIAL_VAT_INVOICE 或 NORMAL_INVOICE}",
    "invoiceRemark": "{开票备注}"
  },
  "invoiceDetailList": [
    {
      "itemName": "{标准项目名称}",
      "goodsServiceTaxCode": "{选定的19位税收分类编码}",
      "spec": "{规格型号}",
      "unit": "{单位}",
      "quantity": "{数量}",
      "amount": "{含税总金额，保留最多4位小数}",
      "unitPrice": "{含税单价 = amount / quantity，除不尽保留13位小数}",
      "taxRate": "{税率}"
    }
  ]
}
```

### 字段映射说明

| 客户表述 | 字段值 |
|----------|--------|
| 蓝字发票 / 正常开票 | `invoiceType: "BLUE_INVOICE"` |
| 红字发票 / 冲红 | `invoiceType: "RED_INVOICE"` |
| 专票 / 增值税专用发票 | `invoiceCategory: "SPECIAL_VAT_INVOICE"` |
| 普票 / 普通发票 | `invoiceCategory: "NORMAL_INVOICE"` |

### 税收编码说明

- 明细行中的 `goodsServiceTaxCode` 为 **必填项（19位纯数字）**
- 必须在前置交互中通过 `tax_query.py` 检索并经客户选择确认后填入
- 严禁留空或未经客户确认直接提交

---

## 注意事项

1. 开票工单调用的 Skill 是 `invoice-creator`（不是 `ticket-creator`）
2. 开票工单创建成功后无 H5 确认页，回复模板为：
   > ✅ 开票工单已创建，工单号：`{ticket_id}`。请等待经办人确认后进行后续开票操作。
3. 如果客户同时选择了工商变更事项和发票开票，需要分别创建两个独立的工单
