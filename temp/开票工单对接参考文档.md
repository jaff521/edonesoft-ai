## 1. 概述

开票工单是一种特殊的工单类型（`orderType = "BIZ_INVOICE"`），通过扩展表 `biz_order_invoice` 存储购方信息，通过 `biz_order_invoice_detail` 表存储开票明细行。

外部系统通过 **开放接口**（静态 Token 鉴权）进行读写，接口路径前缀为 `/bizorder/openapi/invoiceWorkOrder/**`。

---

## 2. 鉴权方式

| 项目 | 说明 |
|------|------|
| 鉴权类型 | 静态 Token（请求头校验） |
| 请求头名称 | `X-Open-Token` |
| 配置项 | 服务端 `bizorder.openapi.token` |
| 生效范围 | 所有 `/bizorder/openapi/*` |
| Token 获取 | 由本系统运维/对接方线下分配 |

**鉴权失败响应**：

```json
{ "success": false, "code": 401, "message": "无效的开放接口 Token" }
```

## 4. 开票工单接口

**Base URL**: `{host}/jeecg-boot/bizorder/openapi/invoiceWorkOrder`

### 4.1 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/list` | 分页列表（含购方/金额等扩展字段） |
| GET | `/queryById?id=` | 聚合详情（主单 + 扩展 + 明细行） |
| POST | `/add` | 创建开票工单（含明细）。**销售方必须已存在于客户信息，否则报错**（见 4.3） |
| PUT | `/edit` | 编辑开票工单 |
| GET | `/getEnterpriseByChatId?wechatMappingKey=` | 按企微会话ID查企业信息（销售方+购买方，合并去重），见 4.4 |
| GET | `/getInvoiceDetailsByChatId?wechatMappingKey=` | 按企微会话ID查历史开票明细（项目名称+税收编码，去重），见 4.5 |

### 4.2 列表查询参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| pageNo | int | 否 | 页码，默认 1 |
| pageSize | int | 否 | 每页条数，默认 10 |
| orderNo | string | 否 | 工单编号 |
| enterpriseName | string | 否 | 企业名称（模糊） |
| creditCode | string | 否 | 信用代码（模糊） |
| orderStatus | string | 否 | 工单状态，如 `PENDING` |

### 4.3 创建接口的销售方校验（v1.2 起）

工单主表中的 `enterpriseName`（可选配合 `creditCode`）即**销售方**，必须已经存在于本系统客户信息（`biz_customer_info`）中：

- 匹配口径：`creditCode` 或 `enterpriseName` **任一精确匹配**到客户即视为存在（`creditCode` 因全局唯一按全局匹配；企业名称在**当前 Token 所属租户**内匹配）；
- 若传了 `customerId`，则校验该客户是否存在；
- **检测不到时直接返回报错，不再自动创建客户**：

```json
{ "success": false, "code": 500, "message": "销售方【上海星辰贸易有限公司】在客户信息中不存在，请先在本系统录入该客户后再创建工单" }
```

对接方应在调用 `/add` 前确保客户已录入（可由业务人员在本系统客户管理/开票工单页面维护）。

### 4.4 按会话ID查询企业信息（去重）

```http
GET /jeecg-boot/bizorder/openapi/invoiceWorkOrder/getEnterpriseByChatId?wechatMappingKey=wrChat_xxxx
X-Open-Token: <your-token>
```

按 `biz_work_order.wechat_mapping_key` 匹配该企微会话下创建过的工单，返回该会话涉及的**销售方 + 购买方**企业信息（固定三个字段），两路数据整合后统一去重：

1. **销售方**：直接取 `biz_work_order` 的 `customer_id / enterprise_name / credit_code`；
2. **购买方**：取该会话工单的 `id`，回查 `biz_order_invoice.order_id`，以 `buyer_name → enterpriseName`、`buyer_credit_code → creditCode` 映射，`customerId` 固定为 `null`；
3. 两路合并返回，按 **企业名称+信用代码**（去空格、信用代码转大写）归一化去重；同一企业既做过销售方又做过购买方时，保留销售方条目（即保留 `customerId`）。

**响应 `result` 示例**（数组）：

```json
[
  {
    "customerId": "2059454092242161666",
    "enterpriseName": "上海星辰贸易有限公司",
    "creditCode": "91310000MA002B002X"
  },
  {
    "customerId": null,
    "enterpriseName": "北京某科技有限公司",
    "creditCode": "91110108MA01XXXXX"
  }
]
```

> `customerId` 为 `null` 表示该企业仅作为**购买方**出现过，尚未在本系统客户信息中建档。

### 4.5 按会话ID查询历史开票明细（去重）

```http
GET /jeecg-boot/bizorder/openapi/invoiceWorkOrder/getInvoiceDetailsByChatId?wechatMappingKey=wrChat_xxxx
X-Open-Token: <your-token>
```

查询该企微会话下**历史开票工单**的明细行（`biz_order_invoice_detail`），重点返回 `item_name`（项目名称）与 `goods_service_tax_code`（税收分类编码）两项，并按此两项组合去重（按创建时间倒序保留最近一次出现），供对接方做开票项目联想/预填使用。

**响应 `result` 示例**（数组）：

```json
[
  {
    "itemName": "*软件开发服务*ERP系统定制开发",
    "goodsServiceTaxCode": "3040201010000000000"
  }
]
```

## 5. 税收分类编码接口

**Base URL**: `{host}/jeecg-boot/bizorder/openapi/taxCategory`

数据来源：`biz_tax_category` 表（商品和服务税收分类编码，当前约 4122 条）。

### 5.1 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/search?keyword=&limit=50` | 模糊搜索（匹配编码/名称/简称），仅返回叶子节点 |
| GET | `/children?parentCode=` | 查询指定编码的子节点 |
| GET | `/getByCode?code=` | 按 19 位编码精确查询 |
| GET | `/page?keyword=&pageNo=&pageSize=` | 分页查询 |

## 6. 数据模型

### 6.1 聚合对象 WorkOrderPage

创建/编辑/详情均使用同一结构：

```json
{
  "workOrder": { ... },
  "invoiceOrder": { ... },
  "invoiceDetailList": [ ... ]
}
```

### 6.2 工单主表 workOrder

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 编辑必填 | 主键，新增可不传 |
| orderNo | string | 否 | 工单编号，留空自动生成（GS+日期+6位序号） |
| enterpriseName | string | **是** | 企业名称（即**销售方**）。创建时须已存在于客户信息，否则报错（见 4.3） |
| creditCode | string | 是 | 统一社会信用代码（用于销售方匹配） |
| customerId | string | 否 | 客户 ID（`biz_customer_info.id`）；不传时按 enterpriseName/creditCode 自动匹配已有客户 |
| agentId | string | 否 | 经办人 ID |
| orderStatus | string | 否 | 强制为 `CONFIRM_BY_A`（待经办人确认） |
| isFinalSubmit | int | 否 | 是否最终提交，1=是 0=否 |
| wechatMappingKey | string | 否 | 微信会话ID，用于关联企微侧边栏会话；4.4 / 4.5 接口以此为查询条件 |

### 6.3 发票扩展信息 invoiceOrder

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| buyerName | string | **是** | 购买方名称 |
| buyerCreditCode | string | 否 | 购买方统一信用代码 |
| invoiceType | string | **是** | `BLUE_INVOICE`(蓝字) / `RED_INVOICE`(红字) |
| invoiceCategory | string | **是** | `SPECIAL_VAT_INVOICE`(专票) / `NORMAL_INVOICE`(普票) |
| invoiceRemark | string | 否 | 开票备注 |

### 6.4 开票明细行 invoiceDetailList

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| itemName | string | **是** | 项目名称，格式：`*税收分类编码简称*客户货物名称`（如 `*鉴证咨询服务*法律服务`） |
| goodsServiceTaxCode | string | **是** | 商品和服务税收分类编码（19位） |
| spec | string | 否 | 规格型号 |
| unit | string | **否** | 单位 |
| quantity | decimal | **是** | 数量 |
| taxRate | string | **是** | 税率，如 `0.06`（6%）、`0`（0%） |
| taxInclusiveAmount | decimal | **是** | 含税金额（价税合计）。已传则直接取该字段；未传则过渡期兼容按 `amount + taxAmount` 计算 |

> 说明：明细**不再接收** `unitPrice`（单价）、`amount`（金额）、`taxAmount`（税额）字段；**含税单价**（`taxInclusiveUnitPrice`）由后台按 `含税金额 / 数量` 自动计算并保留 13 位小数，无需对接方传。

### 6.5 税收分类编码 BizTaxCategory

| 字段 | 类型 | 说明 |
|------|------|------|
| code | string | 合并编码（19位） |
| parentCode | string | 父级编码 |
| name | string | 货物和劳务名称 |
| shortName | string | 分类简称 |
| level | int | 层级深度 0-9 |
| isLeaf | int | 1=叶子节点（可选择用于开票） |

## 7. 完整对接示例

### 7.1 创建开票工单

> **前置条件**：销售方（`workOrder.enterpriseName`/`creditCode`）必须已存在于本系统客户信息中（见 4.3），否则接口直接返回报错，不会自动创建客户。

```http
POST /jeecg-boot/bizorder/openapi/invoiceWorkOrder/add
X-Open-Token: <your-token>
Content-Type: application/json
```

```json
{
  "workOrder": {
    "enterpriseName": "上海星辰贸易有限公司",
    "creditCode": "91310000MA002B002X",
    "agentId": "2059454092242161666",
    "isFinalSubmit": 0,
    "wechatMappingKey": "wrChat_xxxx"
  },
  "invoiceOrder": {
    "buyerName": "北京某科技有限公司",
    "buyerCreditCode": "91110108MA01XXXXX",
    "invoiceType": "BLUE_INVOICE",
    "invoiceCategory": "SPECIAL_VAT_INVOICE",
    "invoiceRemark": "项目一期开发费"
  },
  "invoiceDetailList": [
    {
      "itemName": "*软件开发服务*ERP系统定制开发",
      "goodsServiceTaxCode": "3040201010000000000",
      "unit": "项",
      "quantity": 1,
      "taxRate": "0.06",
      "taxInclusiveAmount": 106000
    },
    {
      "itemName": "*技术咨询服务*数据迁移方案",
      "goodsServiceTaxCode": "3040201030000000000",
      "unit": "次",
      "quantity": 2,
      "taxRate": "0.06",
      "taxInclusiveAmount": 10600
    }
  ]
}
```

**响应**：
```json
{ "success": true, "code": 200, "result": "添加成功！id=2082323735033016330" }
```

**销售方不存在时的失败响应**：
```json
{ "success": false, "code": 500, "message": "销售方【上海星辰贸易有限公司】在客户信息中不存在，请先在本系统录入该客户后再创建工单" }
```

### 7.2 查询详情

```http
GET /jeecg-boot/bizorder/openapi/invoiceWorkOrder/queryById?id=2082323735033016330
X-Open-Token: <your-token>
```

### 7.3 搜索税收编码

```http
GET /jeecg-boot/bizorder/openapi/taxCategory/search?keyword=软件&limit=10
X-Open-Token: <your-token>
```

### 7.4 按会话ID预取企业信息与历史开票明细（推荐流程）

创建工单前后，可用企微会话ID拉取该会话下已出现过的企业信息与历史开票明细，用于销售方选择与明细行联想预填：

```http
GET /jeecg-boot/bizorder/openapi/invoiceWorkOrder/getEnterpriseByChatId?wechatMappingKey=wrChat_xxxx
X-Open-Token: <your-token>
```

```http
GET /jeecg-boot/bizorder/openapi/invoiceWorkOrder/getInvoiceDetailsByChatId?wechatMappingKey=wrChat_xxxx
X-Open-Token: <your-token>
```

两接口均已去重，响应结构见 4.4 / 4.5。

## 8. 字典与枚举

### 8.1 工单状态 biz_order_status

| item_value | item_text |
|------------|-----------|
| PREPARING | 材料准备中 |
| CONFIRM_BY_C | 待客户确认 |
| CONFIRM_BY_A | 待经办人确认 |
| PENDING | 待提交 |
| DISPATCHED | 已下发RPA |
| RUNNING | RPA执行中 |
| WAIT_CONFIRM | RPA执行完成待确认 |
| DONE | 已办结 |

### 8.2 开票类别 invoiceType

| item_value | item_text |
|------------|-----------|
| BLUE_INVOICE | 蓝字发票 |
| RED_INVOICE | 红字发票 |

### 8.3 发票类别 invoiceCategory

| item_value | item_text |
|------------|-----------|
| SPECIAL_VAT_INVOICE | 增值税专用发票 |
| NORMAL_INVOICE | 普通发票 |

### 8.4 税率常见值

| 值 | 说明 |
|----|------|
| 13% | 一般货物/劳务 |
| 9% | 不动产/运输 |
| 6% | 现代服务业 |
| 3% | 简易征收 |
| 0% | 免税/零税率 |
